Backend · Architecture

Why separate Domain, Application and Infrastructure?

Clean Architecture helps keep business rules independent from frameworks and external services.

Read the note

The Domain layer expresses core concepts and rules. The Application layer coordinates use cases. Infrastructure handles details such as database access and external integrations. The API layer exposes the application to clients. This separation can make a growing codebase easier to test and change, provided the boundaries are respected rather than added only for folder structure.

Learning technology · Offline-first

Designing for low-connectivity learning

Offline-first should be a clear data and synchronization strategy—not just a marketing label.

Read the note

A practical offline-first design identifies which lessons and resources can be stored locally, how updates are synchronized, how conflicts are handled, and which features still require a network connection. Local persistence, clear sync states, and honest user messaging are essential. AI-powered features may still require an online service unless an on-device model is deliberately implemented.

Computer science · Fundamentals

Understand Big-O before optimizing

Complexity describes how an algorithm's resource use grows as input size increases.

Read the note

Big-O gives an upper-bound growth description, not an exact runtime in seconds. A single loop over n items is commonly O(n); two nested loops over n items are commonly O(n²). Sequential loops add their costs, while the dominant growth term describes the overall asymptotic behavior. Always consider the actual input and algorithm before choosing a data structure.
